# 2026-11-26｜自定义异常与错误边界

> 主线延伸——类与对象 · Python · 建议用时50–60分钟 · 发布内容不表示已经完成。

## 今日目标

- 让业务失败使用清楚、可单独捕获的自定义异常。
- 用 `raise NewError(...) from original` 保留底层原因。
- 只在能处理错误的边界捕获异常，避免宽泛吞错。

## 从内置异常到领域异常

`ValueError` 能说明“值不合法”，却不能直接区分“未知状态”和“禁止的状态转换”。可以先定义一个继承自 `Exception` 的领域错误族：

```python
class DomainError(Exception):
    pass

class UnknownStatusError(DomainError):
    pass

class InvalidTransitionError(DomainError):
    pass
```

调用者既能只捕获 `UnknownStatusError`，也能在应用边界统一捕获 `DomainError`。不要继承 `BaseException`：它还覆盖 `KeyboardInterrupt`、`SystemExit` 等通常不应被业务代码截住的控制信号。

## 转换错误并保留原因

按枚举名称查找失败时底层抛出 `KeyError`。对外可以换成业务语义更清楚的错误，同时用 `from` 保留因果链：

```python
try:
    return EnrollmentStatus[text.strip().upper()]
except KeyError as error:
    raise UnknownStatusError(f"unknown status: {text!r}") from error
```

这样界面层看到的是领域错误，调试时仍能通过 `__cause__` 找到原始 `KeyError`。只捕获自己准备转换或恢复的具体异常，不用空的 `except:` 隐藏程序缺陷。

## 错误边界

解析函数负责把外部文本变为枚举；状态函数负责检查转换规则；最外层命令行或网页边界才决定如何向用户显示错误。底层函数不打印“成功”，也不悄悄返回 `None`，而是返回有效结果或抛出明确异常。

## 易错点

| 易错做法 | 正确做法 |
| --- | --- |
| 自定义异常继承 BaseException | 通常直接或间接继承 Exception |
| 捕获 Exception 后什么也不做 | 只捕获能处理的具体类型 |
| 转换异常时丢掉原错误 | 使用 `raise ... from error` |
| 非法转换仍返回原对象 | 相同状态可复用；禁止方向应抛明确错误 |

## 动手与验收

1. 为未知状态与非法转换分别定义异常。
2. 验证异常链的 `__cause__` 是 `KeyError`。
3. 覆盖合法转换、毕业后回退、空学号、非字符串和未知状态。
