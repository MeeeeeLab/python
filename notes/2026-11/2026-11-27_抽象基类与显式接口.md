## 用父类写明共同契约

当多个报告格式器都必须提供`format(records)`时，可以把接口放进抽象基类：

```python
from abc import ABC, abstractmethod

class ReportFormatter(ABC):
    @abstractmethod
    def format(self, records):
        """Return a complete report."""
```

具体类显式继承`ReportFormatter`并实现`format`后才能实例化。如果子类遗漏实现，Python会在实例化时抛出`TypeError`，比运行到某个不存在的方法才失败更早。

## 抽象方法与共享实现

ABC不必只有空方法。它可以提供已实现的公共校验方法，子类直接复用；`@abstractmethod`只标记每个具体子类必须补齐的部分。这样接口规则和共享行为位于同一处，但不要把所有细节都塞进父类。

## 与Protocol对比

ABC通常使用名义子类型：类需要显式继承，`isinstance`和`issubclass`可以直接检查这条关系。Protocol侧重结构化子类型：只要对象形状满足方法要求，静态类型检查器就可接受，不一定显式继承。二者不是谁替代谁：需要运行时基类关系和共享实现时ABC更合适；希望低耦合的静态接口时Protocol更轻。

## 易错点

| 易错理解 | 正确理解 |
| --- | --- |
| 继承ABC就自动完成接口 | 仍必须实现所有抽象方法 |
| abstractmethod会自动生成逻辑 | 它声明契约，具体行为仍由子类提供 |
| ABC只能含抽象方法 | 可以包含普通共享方法 |
| ABC与Protocol完全相同 | 前者偏名义关系，后者偏结构化关系 |
