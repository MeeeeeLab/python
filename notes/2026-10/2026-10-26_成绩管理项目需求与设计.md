## 可运行骨架

```python
COMMANDS = {
    "1": "add",
    "2": "find",
    "3": "list",
    "4": "save",
    "0": "quit",
}


def create_student(student_id, name, score):
    if not student_id.strip() or not name.strip():
        raise ValueError("id and name must not be empty")
    if not 0 <= score <= 100:
        raise ValueError("score must be between 0 and 100")
    return {"id": student_id.strip(), "name": name.strip(), "score": score}


def choose_action(choice):
    return COMMANDS.get(choice.strip(), "invalid")


def run_checks():
    assert choose_action(" 1 ") == "add"
    assert choose_action("9") == "invalid"
    assert create_student(" S01 ", " Amy ", 95) == {
        "id": "S01", "name": "Amy", "score": 95
    }
    for args in [("", "Amy", 80), ("S01", "", 80), ("S01", "Amy", 101)]:
        try:
            create_student(*args)
        except ValueError:
            pass
        else:
            raise AssertionError(args)


if __name__ == "__main__":
    run_checks()
    print("design checks: OK")
```

运行：`python3 grade_system_design.py`。本次已核对合法命令、非法命令、空 ID、空姓名和越界成绩，输出 `design checks: OK`。

## 设计理由

- `COMMANDS` 集中保存菜单映射，避免多个分支重复写字符串。
- `create_student` 只负责建立一条合法记录，不负责保存或打印。
- `choose_action` 对输入先 `strip()`，让界面层和业务层边界清楚。
- 异常是契约的一部分；不能只测成功样例。

## 易错点

- 用姓名当唯一键，遇到同名学生会覆盖。
- 菜单函数同时读取输入、修改数据、写 CSV，难以单独测试。
- 把空字符串或 101 分悄悄保存。
- 今天就实现所有功能，导致职责混乱且难以验收。
